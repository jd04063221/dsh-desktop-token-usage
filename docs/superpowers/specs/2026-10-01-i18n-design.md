# Token 用量看板 —— 多语言（i18n）设计

> 状态：待评审 · 2026-10-01 · 分支 `feat/i18n`
> 关联：[`docs/DESIGN.md`](../../DESIGN.md)、[`README-zh.md`](../../../README-zh.md)、DSH `@deepseek-ai/dsh-client-locale` 文档

## 1. 目标

1. 插件界面文案**全部**来自 DSH 的语言服务，语言跟随 **DSH Desktop 自身设置**（用户不需要在插件里选语言）。
2. **一一对应** DSH 支持的语言：DSH 内置 `zh` 与 `en` 两本字典，我们用同名 id 提供两本完整字典。
3. 以**语言包**方式（`addLanguage`）扩展 DSH 目录，覆盖用户点名要处理的三种情形：
   - 繁体：`zh-TW`、`zh-HK`（港澳台用语不同，必须分开）
   - 阿拉伯语：`ar`（RTL，界面要求最高）
4. 按 i18n 标准处理**数字、单位、日期、复数、方向**，不做「中文模板 + 英文替换」式的伪本地化。

## 2. 非目标

- 不新增插件自己的语言选择器（选择权在 DSH 设置里）。
- 不改 README / CHANGELOG / `docs/` 的语言（文档本来就是中英双语）。
- 不翻译 DSH 自身的界面（那是 DSH 的事；我们扩展的语言包只提供**本插件命名空间**的字典）。
- 不改数据口径、图表几何语义（只改文案与方向相关的镜像）。

## 3. 事实依据（已核实，来自本机 DSH 0.2.0-rc.2 包内文档与源码清单）

| 事实 | 证据 |
|---|---|
| DSH 内置界面语言**只有 zh + en** | 包内文档「`src/locales/` —— 内置的 `zh`、`en` 字典」；所有 DSH 客户端包只带 `locale/en.json` + `locale/zh.json` |
| 注册字典 | `ctx.locale.register(ns, { zh, en })`；**两个内置 locale 必须齐全**，否则注册失败 |
| 取译文 | `ctx.locale.bind(ns)` 或框架注入的 `t` 席位；查找顺序：本命名空间 → `common` → 显示键名 |
| 扩展语言 | `ctx.locale.addLanguage({ id, label, fallback })` + `ctx.locale.register(ns, id, {...})`；id 是非空 ASCII BCP 47 风格标签，回退目标必须已注册且**链必须以 `en` 终止** |
| 语言选择器归属 | 语言包会进入 DSH 的选择器；`locale.preference` 由 Host 持久化；未选择时按系统语言自动探测（自动选择是临时状态） |
| 语言切换的实时性 | 已挂载后注册字典**无需重新挂载**即生效；连续同步走 `locale/change` 事件或 `LocaleFace` 的 `getSnapshot`/`subscribe`（快照含**生效 locale、可选 locale 列表、单调 revision**） |
| 方向 | 快照**不含** direction（RTL）信息 → **方向由本插件自己判定** |
| 插件清单文案 | 包内 `locale/<lang>.json`（`{ meta: { title, description } }`），本仓库**已有** `locale/zh.json` + `locale/en.json` |
| Host（node 半边） | **没有** locale 服务 → Host 生成的用户可见字符串必须另行处理（见第 8 节） |

## 4. 语言矩阵

| id | 来源 | 回退链 | 说明 |
|---|---|---|---|
| `zh` | DSH 内置 | `zh → en` | 简体中文（现任文案基线） |
| `en` | DSH 内置 | `en` | 英文；**所有回退链的终点** |
| `zh-TW` | 本插件语言包 | `zh-TW → zh → en` | 臺灣正體；用词与 zh 不同（见第 13 节） |
| `zh-HK` | 本插件语言包 | `zh-HK → zh → en` | 香港繁體；用词与 zh-TW 亦不同 |
| `ar` | 本插件语言包 | `ar → en` | 阿拉伯语；RTL、复数六类、阿拉伯-印度数字 |

其它语言（DSH 未来新增或用户系统语言为 ja/ko/fr…）**不注册语言包**，由回退链自动落到 `en`——这正是 DSH 文档规定的行为，不需要我们为每种语言兜底。

不做的事：不为 `zh-Hant` 单独注册（`zh-TW`/`zh-HK` 已覆盖；若将来 DSH 引入 `zh-Hant`，加一条语言包即可）。

## 5. 运行时机制（客户端）

```js
// client.js
const NS = 'dsh-desktop-token-usage'

export const inject = ['locale']   // 与既有的 'slots' / 'remote' 合并

function apply(ctx) {
  // 1) 扩展语言目录（本插件带来的语言）
  ctx.effect(() => ctx.locale.addLanguage({ id: 'zh-TW', label: '繁體中文（臺灣）', fallback: 'zh' }), 'dtu: lang zh-TW')
  ctx.effect(() => ctx.locale.addLanguage({ id: 'zh-HK', label: '繁體中文（香港）', fallback: 'zh' }), 'dtu: lang zh-HK')
  ctx.effect(() => ctx.locale.addLanguage({ id: 'ar', label: 'العربية', fallback: 'en' }), 'dtu: lang ar')

  // 2) 注册字典：两个内置 locale 一起给（DSH 要求齐全），语言包各自单给
  ctx.effect(() => ctx.locale.register(NS, { zh: ZH, en: EN }), 'dtu: dict zh/en')
  ctx.effect(() => ctx.locale.register(NS, 'zh-TW', ZH_TW), 'dtu: dict zh-TW')
  ctx.effect(() => ctx.locale.register(NS, 'zh-HK', ZH_HK), 'dtu: dict zh-HK')
  ctx.effect(() => ctx.locale.register(NS, 'ar', AR), 'dtu: dict ar')

  // 3) 把 t 与生效 locale 注入到 slot 组件
  ctx.slots.register({ name: 'main', key: PANEL_ID, inject: () => ({ ...face(), t, locale: activeLocale }) }, Dashboard)
}
```

- `t` 由 `ctx.locale.bind(NS)` 得到；`activeLocale` 取自 LocaleFace 快照。
- **注入函数在 locale revision 变化时会被重算**（DSH 的 slot 工厂机制），因此语言切换无需重启/重挂载；实现时必须**真机验证**这一点（见第 12 节）。若实测不重算，退化为：在组件内订阅 `LocaleFace` 的 `subscribe`，用 `useState` 计数器强制重渲染（`useSyncExternalStore` 的 `getSnapshot` 必须返回稳定值，故用 subscribe+计数器更安全）。
- 语言方向（RTL）由本插件判定：内置 RTL 语言集合（`ar`、`he`、`fa`、`ur`…）→ 根节点加 `dir="rtl"` 与 `data-dtu-dir="rtl"`。

## 6. 文案组织

- **单一命名空间** `dsh-desktop-token-usage`；键名 `区域.名称`，例如：
  - `range.7d` / `range.custom`、`source.client` / `source.cli` / `source.subagent`
  - `card.tokens` / `card.turns` / `card.requests` / `card.activeDays` / `card.hitRate` / `card.topModel` / `card.topProvider`
  - `trend.title` / `trend.hint`、`breakdown.title`、`heat.title` / `heat.metric.tokens` / `heat.metric.turns`
  - `config.groupBy` / `config.groupBy.auto` / `config.palette.primer` / `config.save` / `config.readonly`
  - `state.loading` / `state.empty` / `state.error.summary` / `state.error.config`
  - `foot.updated` / `foot.source` / `foot.inference`、`tip.tokens` / `tip.turns` / `tip.requests`
  - `a11y.rangeStart` / `a11y.rangeEnd` / `a11y.metric`（`aria-label`）
- **插值**：`{name}` 占位符由本插件的 `t` 包装层替换（`t(key, { hours: 6 })`），例如 `window.hours` → `近 {hours} 小时` / `Last {hours} hours`。
- **复数**：用 `Intl.PluralRules(locale)` 选键，键后缀为 CLDR 类别（`one`/`other`，阿拉伯语会用到 `zero`/`two`/`few`/`many`）。出现计数的键必须成对存在，例如 `card.turns.one` / `card.turns.other`；**简体与繁体也要提供全部类别**（内容可相同），因为 `register(ns, { zh, en })` 要求每个键在两种内置 locale 里都存在。
- **不进入字典的字面量**：纯符号（`·`、`—`、`%`）、色值、日期键（`YYYY-MM-DD` 数据键）、日志与技术标识。测试会禁止其它 CJK 字面量残留（第 10 节）。

## 7. 数字、单位、日期（i18n 标准）

| 场景 | 现实现 | 目标实现 |
|---|---|---|
| 千分位整数 | `toLocaleString('en-US')` | `Intl.NumberFormat(locale)`（实测 ar 默认仍用拉丁数字 `1,234,567`；若要阿拉伯-印度数字需显式 `ar-u-nu-arab`——见第 14 节未决项） |
| 紧凑数字 | 手写 `亿`/`万` | `Intl.NumberFormat(locale, { notation: 'compact', maximumFractionDigits: 2 })`（实测：zh `14.52亿` / `125万`、zh-TW `14.52億` / `125萬`、zh-HK 与 en `1.45B` / `1.25M`、ar `1.45 مليار`） |
| 百分比 | 手写 `toFixed(1) + '%'` | `Intl.NumberFormat(locale, { style: 'percent', maximumFractionDigits: 1 })`（ar 会本地化百分号方向） |
| 页脚时间戳 | `toLocaleString('zh-CN')` | `Intl.DateTimeFormat(locale, { dateStyle: 'medium', timeStyle: 'medium' })` |
| X 轴日期 | `day.slice(5)` | `Intl.DateTimeFormat(locale, { month: '2-digit', day: '2-digit' })` |
| 星期/月份轴 | 硬编码 `一…日`、`N月` | 星期 `{ weekday: 'narrow' }`（zh 给 `二`，en 给 `T`，瑞士表风格，适合 22px 轴宽）；月份用 `{ month: 'short' }`（zh 给 `10月`，en 给 `Oct`）——**不要用 `narrow`**，英文窄月份是单字母 `O`，无法辨认 |

**注意**：紧凑/百分比格式换用 `Intl` 后，与现有测试里写死的字符串（`125.0万`、`92.3%` 等）**会有差异**。这是"用标准换稳定性"的一次性代价，测试改为**表驱动 + 按 locale 固定期望值**。

数字在 RTL 文本中的嵌入：所有数字/百分比块加 `unicode-bidi: isolate; direction: ltr`（或 `<bdi>`），避免阿拉伯语环境下 `92.3%` 被重排成 `%92.3`。

## 8. Host（node 半边）的三处用户可见字符串

| 字符串 | 处理 |
|---|---|
| `近 N 小时` / `近 N 天` / `累计`（`lib/session-usage.js` 生成并随载荷下发） | **客户端按 `block.id` + 配置渲染**（`hours` / `days` / `all` 三个稳定 id）；Host 继续照发原字符串，作为**老客户端**的回落。Host 零改动。 |
| 4 条 `Schema.description`（DSH 设置页渲染） | Host 侧无 locale 服务 → 改为**语言中立短句**：`0–23 · 0 = off`、`1–30 · 0 = off`、`model / provider / both`、`primer / cvd / muted · light/dark follows the system`。既有的中文散文删除（原文案可在 README 里保留双语说明）。 |
| 插件在 DSH 里的名称/描述 | 已由 `locale/zh.json` + `locale/en.json` 本地化；本次为 `zh-TW`/`zh-HK`/`ar` 各加一份 |

## 9. 清单文件 `locale/*.json`

新增 `locale/zh-TW.json`、`locale/zh-HK.json`、`locale/ar.json`（结构同现有 `meta.title` / `meta.description`）。
id 大小写与运行时 id 保持一致（`zh-TW`），文件名沿用 DSH 惯例 `<id>.json`；实现时以真机选择器显示为准，若解析器要求小写则统一改成 `zh-tw`（**测试**：`locale/` 目录文件名集合 = 运行时语言 id 集合）。

## 10. 测试策略

1. **键奇偶校验**：`zh` 与 `en` 键集合完全一致；`zh-TW`/`zh-HK`/`ar` 的键集合是 `zh` 的**子集 ∪ 相同**（允许语言包只覆盖部分键，其余走回退链——按 DSH 语义，未命中的键沿链查找）。
2. **无游离字面量守卫**：`client.js` 中除字典块外不得出现 CJK 字符（正则扫描 + 允许清单），这是 i18n 烂尾的头号防线。
3. **插值/复数**：`t('window.hours', { hours: 6 })` 三语快照；`Intl.PluralRules` 选键在 ar 上覆盖 `zero/two/few/many`。
4. **格式表驱动**：同一批数值在 `zh`/`en`/`zh-TW`/`ar` 下的紧凑、百分比、日期期望值（固定 ICU 版本；必要时只在断言里比较结构而非具体字形，避免 Node ICU 与渲染端差异）。
5. **渲染冒烟**：harness 的假 `ctx.locale` 支持指定 locale；`zh` 保留全部既有断言，另加 `en`/`zh-TW`/`ar` 各一组关键断言。
6. **RTL 几何锁**：`dir="rtl"` 时 plot 内缩（`--dtu-plot-l/-r`）、命中率刻度侧、热力图周一周标签轴侧、悬停框翻边方向全部镜像；用与现有几何锁同一套 CSS 字符串断言。
7. **兼容性**：老 Host（载荷带中文 `label`）下客户端仍渲染本地化标题；老客户端（无 locale 服务）不受影响。
8. **清单文件**：`locale/` 文件名集合与运行时 id 集合一致；每份含 `meta.title`/`meta.description`。

## 11. 兼容性与降级

- **没有 locale 服务**（DSH 版本更老）：`ctx.locale` 不存在时，客户端回落到内置的 `zh` 字典 + `t` 直通实现，功能不降级（只是不能切语言）。
- **未注册语言**：DSH 自动走回退链到 `en`。
- **加载顺序**：语言定义与字典可任意顺序注册；两者都是 `ctx.effect` 拥有的副作用，卸载即回收（DSH 文档保证）。
- **老 Host**：窗口标题回落逻辑见第 8 节；Host 的 schema 描述变更对老客户端无影响。

## 12. 验收清单（真机）

1. DSH 设置里把语言切成英文 → 看板文案**即时**变英文（不重启、不重挂载）。
2. 语言选择器里能看到`繁體中文（臺灣）`、`繁體中文（香港）`、`العربية`。
3. zh-TW / zh-HK 术语抽查：缓存/快取、文件/檔案、设置/設定、刷新/重新整理、供应商、轮次、请求。
4. `ar` 视觉验收：整体 RTL、图表时间轴方向、tooltip 不越界、数字与百分号不被重排、阿拉伯文字行高与字号、数值列仍为 LTR 且等宽对齐。
5. 三种语言下**布局敏感点**复查：配置下拉（96px 宽）、chip、页脚三行、tooltip 四行、统计卡标题换行。
6. 老 Host（不重启）场景：窗口标题仍正确显示。

## 14. 风险与未决

1. **`Intl` 紧凑格式替换手写单位**：标准优先建议采纳，但会改变现有断言与显示细节。已实测的两个**意外但真实**的 CLDR 行为需要你知情：
   - `zh-HK` 的紧凑单位是 **拉丁 K/M/B**（`1.25M`），不是 `萬/億`（`zh-TW` 才是 `萬/億`）。这是 CLDR 数据，不是我们的 bug；若你要求港澳也用 `萬/億`，需要在 `zh-HK` 字典里自带单位并在包装层里覆盖 `Intl`。
   - `ar` 默认用**拉丁数字**（`1,234,567`），要阿拉伯-印度数字（`١٢٣٤`）得显式 `ar-u-nu-arab`。请确认你要哪一种。
2. **图表几何是否镜像**（RTL 下时间轴方向）：建议**只镜像界面外壳**（标签、内缩、tooltip、侧栏），**时间轴仍从左到右**（数据可视化惯例，且几何测试保持可读）。若你要求完全镜像，工作量与风险显著上升。
3. **设置页 4 条描述**改为语言中立短句 → 中文用户会失去散文说明（README 保留双语解释作为补偿）。
4. **繁体术语**需母语复核（第 13 节为初稿）。
5. **`ar` 的行高/字体**：Windows 默认字体栈对阿拉伯语渲染一般，可能需要显式 font-family 与 line-height 覆盖。
6. **百分比在 RTL 下带双向控制符**：实测 `Intl` 的 ar 百分比输出是 `92.3‎%‎`（含 U+200E），我们现有的 CSS/断言按字符比较会不稳定——因此断言按结构（数值 + 百分号）而非逐字符比较，并在样式上对数值块加 `unicode-bidi: isolate`。
7. **`en` 的窄月份是单字母**（`O`），已因此在第 7 节改用 `month: 'short'`；若 `zh` 的短月份在窄卡片下过宽，需回退为数字 + 单位。
