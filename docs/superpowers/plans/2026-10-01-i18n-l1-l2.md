# 多语言（i18n）第 1、2 梯队 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **状态：已实施完成。** 勾选项是已完成项，最后两节记录验证证据与未做部分。

**Goal:** 让看板与侧边栏文案**跟随 DSH 自身的语言设置**（插件不自带选择器），本次交付第 1 梯队（`en` `zh` `zh-TW` `zh-HK`）与第 2 梯队（`de` `fr` `es` `it` `ja` `ko`）共 10 种语言，数字/百分比/日期/星期月份/复数全部走 `Intl`。

**Architecture:** 文案的**唯一真相**是 `locales/<id>.json`（一语言一文件，可并行翻译）；`scripts/build-dicts.mjs` 把它生成进 `client.js` 里一段带标记的 `DICT` 块，成品仍是**零依赖单文件**、仍无构建。运行时用 `ctx.inject(['locale'])` 可选地接入 DSH 的语言服务：注册 8 个语言包（`addLanguage`）与 10 本字典（`register`），并在**每次渲染**重读生效语言（`useLocale()` → `syncLocale()`），因此切语言无需重启或重新挂载；没有该服务时按 `navigator.languages` 回落。数字/日期/百分比/复数一律由 `Intl`（按 locale 缓存 formatter）产出。Host 半边没有语言服务，因此四条 `Schema.description` 改成语言中立短句、诊断改英文。

**Tech Stack:** 纯 JS（无构建、无 i18n 库），`node --test` + 自建假 React/DOM 与假 locale 服务（`test/client-smoke.test.mjs`），`Intl`（Node 26 / ICU 78.3）。

**Spec:** `docs/superpowers/specs/2026-10-01-i18n-design.md`

**测试命令（每个任务都用这一条）：** `node --test "test/*.test.mjs"`（等价于 `npm test`）

### Task 1: 冻结键集与基线字典（`en` / `zh`）

**Files:** `locales/en.json`、`locales/zh.json`

- [x] **Step 1:** 从 `client.js` 里清出全部用户可见字面量，定成 `区域.名称` 键（`range.*`、`source.*`、`config.*`、`card.*`、`section.*`、`heat.*`、`tip.*`、`foot.*`、`error.*`、`a11y.*`、`lang.*`）。
- [x] **Step 2:** 四组计数文案定成复数键：`heat.legend`、`unit.turns`、`unit.sessions`、`unit.files`，后缀按 `Intl.PluralRules(locale)` 的类别。
- [x] **Step 3:** `lang.<id>` 存**语言自称**（`繁體中文（臺灣）`、`Deutsch`…），每本字典里都相同——它进的是 DSH 的选择器，不能随当前语言变。
- [x] **Step 4（验证）:** `en` 104 键、`zh` 100 键；非复数键两侧完全一致，差 4 个是 `en` 的 `one` 类别。

### Task 2: 生成器与不变量测试

**Files:** `scripts/build-dicts.mjs`、`test/i18n.test.mjs`

- [x] **Step 1:** 生成器：读 `locales/*.json` → 校验 → 用标记注释替换 `client.js` 里的 `DICT` 块，**保留原文件行尾**（Windows 上是 CRLF）。
- [x] **Step 2:** 校验规则：非复数键必须与 `en` 完全一致；复数键集合必须**精确等于**该语言的 CLDR 类别（多一个少一个都红）；`heat.legend.*` 必须含 `{scope}`/`{days}`/`{total}`/`{unit}`。
- [x] **Step 3:** 三种模式：默认写盘、`--check`（比对，不写）、`--validate --only=<id>`（只校验一种语言，供翻译并行时自查）。`--only` 只影响本次调用，不能用于提交。
- [x] **Step 4:** `test/i18n.test.mjs`：生成同步（逐字节）、键奇偶、**游离文案守卫**（`client.js` 除字典块外不得出现 CJK/全角字符）、`index.js` 不得出现 CJK、`PACKS` 与 `locales/` 与 `locale/` 三者一致、文档矩阵与切换条、文档结构（标题层级序列 / 版本号 / 仓库内链接目标）。
- [x] **Step 5（验证）:** 生成同步测试在“手改生成块”的突变下变红。

### Task 3: `client.js` 结构改造

**Files:** `client.js`

- [x] **Step 1:** 新增 locale 段：`DICT` 生成块、`PACKS` 与 `FALLBACKS`（`zh-TW→zh→en`、`zh-HK→zh→en`、其余 `→en`）、`supportedId()`（含 `zh-Hans/zh-CN/zh-SG`、`zh-Hant/zh-TW/zh-HK/zh-MO` 别名与去掉子标签的主语言匹配）、`syncLocale()`、`useLocale()`。
- [x] **Step 2:** `Intl` 格式层（按 locale 缓存）：`grouped`/`compact`/`percent`/`stamp`/`dayLabel`/`calendar()`（星期一为首日的窄星期与短月份名）。`compact` 有一个例外：某语言在该量级**没有**紧凑单位时 `Intl` 会退回不带千分位的裸数字（`zh` 的 5200 会变 `5200`），这种情形交回 `grouped`。
- [x] **Step 3:** 所有字面量换成 `t()`；`RANGES`/`SOURCES`/`CHIP_GROUPS`/`HEAT_METRICS` 的 `label` 改 `labelKey`；配置窗口标题按 `block.id` + `card.hours`/`card.days` 现算（Host 仍发中文串，作为老客户端回落）。
- [x] **Step 4:** 两处本地失败（“用量服务返回了无法识别的响应”“配置读取失败”）不再存句子，改存**键**（`errorKey`/`configErrorKey`），渲染时翻译。
- [x] **Step 5:** `apply()` 里 `ctx.inject(['locale'])`：每种语言一个 `addLanguage`、`register(NS, {zh, en})` 一次给两个内置 locale、其余每种语言一次 `register`、`localeFace` 归零的清理 effect。**不进**插件 `inject` 数组——没有语言服务时回调不跑，按 `navigator` 回落，功能不降级。
- [x] **Step 6（验证）:** 中文下既有断言全部保留（只改 `Intl` 后的格式期望：`125.0万`→`125万`、`80.0%`→`80%`）；`en` 下新增一整组断言。
